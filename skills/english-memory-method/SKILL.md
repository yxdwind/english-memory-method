# English Memory Method(英语篇章背诵法)v2.40.0

帮助用户快速背熟英文篇章。核心流程:**拆骨架 → 串关键词并焊成链 → 链式复述(L1→L5 阶梯)→ 间隔复习**;最后交付结构图(SVG)+ HTML 背诵方案 + 挖空自测。回复语言与用户一致。

## 核心理念(v2 新增)

**记住 1 条生成规则,而不是 N 个孤立点。**孤立钩子=断点:钩子要背、顺序要背、钩子↔句子映射也要背(三重负担)。
修复方向:钩子之间必须有逻辑/画面/因果连接--结构会自动"推"出下一句,能被推出的内容不需要背。

## 工作流程

> 版本来历、CI 自检标识(`EMM_*`)与历史 bug 修复记录已迁出至 `CHANGELOG.md`;本节只保留行为规则,减少生成上下文噪声。

### Step 0 · 模式识别(先选体裁)

拿到文章后,先判断是哪种**体裁**——决定后续步骤是否启用:

| 体裁 | 句数 | 段落 | 启用专属组件 |
|---|---|---|---|
| 短文(议论文/说明文/叙事文片段) | ≤15 句 且 ≤2 段 | 1~2 段 | 基础流程(Step 1-8) |
| 长文(议论文/说明文/叙事文长篇) | >15 句 或 ≥3 段 | 多段 | 基础流程 + **长文段落单元**(每段 h2 标 `4.N`) + 3. 分段进度仪表 |
| 演讲稿(用户输入含"演讲稿/发言稿/演讲",或文章呈"开场钩→论点展开→升华收尾"三幕结构:TED/比赛/典礼/自拟发言稿等) | 任何 | 短段多句 | 基础流程 + **3. 演讲骨架(三幕结构)** + 朗读要点 |

不启用"演讲骨架"的文章**不要**填 §3. 演讲骨架内容;不启用"长文段落单元"的文章**不要**用 `4.N` 命名前缀(自动退化为整篇一线)。

### Step 1 · 拆骨架(先记逻辑)

1. 数清段落数和句子数(如"4 段 11 句"),识别每段逻辑角色:总起 / 定义 / 类比 / 对比 / 举例 / 转折 / 递进 / 结论 / 金句。
2. 每段提炼一行主线,确保主线覆盖段内全部句子。
3. 按"结构图规范"生成 SVG 结构图(`assets/<topic>-structure.svg`)。

### Step 2 · 串关键词,并焊成链(钩子不许是断点)

- 每句提炼 1~2 个钩子词:关键名词/动词/搭配、数字、押韵词、逻辑路标词。
- 输出 Markdown 表格,每段一张,三列:`原句 | 关键词钩子 | 中文提示`。表格作为独立 Markdown 块输出,前后留空行。
- **关键升级:钩子表只是 L1 脚手架,必须立即"链式化"**--按文体三选一:
  - **问题链法**(议论文/说明文首选):把每句变成"上一个问题的答案";背之前先写问题清单(中文即可),复述=自问自答,问完最后一个问题文章正好讲完。
  - **电影法**(叙事/描写类):关键词编成 30 秒小电影,镜头间要有时间/空间/因果连续性;接不上就加荒诞过渡画面(越怪越好记)。
  - **轨道法**(通用兜底):逻辑连接词=铁轨(but/so/because/still/however),实词=车厢;先背"铁轨句"--只留连接词+主谓骨架,复述时铁轨铺到哪,实词车厢自然进站。

### Step 3 · 链式复述五级阶梯(三遍法的"复述"按此执行)

- **L1** 看关键词表复述(脚手架级,练句子展开)
- **L2** 看结构图/问题清单复述(只剩骨架,练段落记忆)
- **L3** 只看标题复述(只剩路标,练全文串联)
- **L4** 空手复述(链在脑内--真正带走的能力)
- **L5** 转述给别人听(60~90 秒输出检验,记忆强度最高)

规则:每级至少隔一次复习再升级;跳级=断裂=假流利(脚手架在时顺、拆掉就崩)。**L5 的验收标准见「L5 费曼检验」——不是"说够 90 秒"就算过。**

### Step 4 · 三遍法(当天,每段 15~20 分钟)

1. **理解朗读 ×3**:先查清生词搭配,大声朗读 3 遍。
2. **链式复述 ×2**:合上书,走问题链/电影/铁轨--从 L1 开始,能升就升;卡住就瞄一眼钩子词。
3. **默写 + 红笔纠错**:默写整段,对照原文改错,错处重点重背。

### Step 5 · 艾宾浩斯复习计划

时间点:背完后 5 分钟 → 当晚睡前(全文背诵 + 默写)→ 第 2 天早(挖空自测)→ 第 3 天(只背错句)→ 第 7 / 15 天(快背全文)。
**复习 = 阶梯升级(L2→L3→L4→L5),不是原地重复背。**排期执行顺序、每日新学上限与跨段交错规则见「复习调度硬规则」;到期日算法本身不变。

### Step 6 · 找记忆钩子

从文中找出并教给用户:

- 头韵:practical & practicable、will and determination
- 押韵:from the cradle to the grave
- 排比:fame, wealth, accomplishments;cry, sweat, complain, curse
- 对比:sweetest fruit ↔ bitterest ordeal;hugging = closeness ↔ handshake = formality
- 同义换词:constant ↔ continuous(作者避免重复)
- 首尾呼应:thousands of men and women ↔ thousands of other people
- 数字锚点:a quarter or half of a mile、every two weeks
- 逻辑路标词:on the other hand、interestingly enough、whereas、traditionally(路标 = 段落顺序)
- 引号金句:"I like you and I care about you."(一句顶三句)

**三层钩子链**:方案 HTML 第 15 节「记忆钩子」=「文内语言钩」+「三层钩子链」两部分,前者照旧找头韵/押韵/排比/对比/换词/呼应/数字/路标/金句,后者每段一条、专治三大断点:

- **层1 段钩**:每段 1 个画面感大钩(≤8 字),负责"想起这段讲什么"。
- **层2 句钩链**:段内每句 1 个 2~4 字微型钩,按原句顺序串成一行;钩与钩之间必须标**逻辑桥**:因果 `⇒`、转折 `↔`、递进 `→`、并列 `＋`、举例 `:`。桥接不上的链条=断点,优先重做;若确无逻辑关联(如并列列举、独立金句、纯修辞),允许退化为同义/意象钩并显式标「·」或「无桥」,避免硬编牵强连接。
- **层3 英文锚点**:每个句钩后挂原句 2~3 个英文锚词(主谓核心/标志性短语/数字),格式 `[anchor words]`;路径=中文钩→锚词→原句,解决中文概括回不到英文的问题。

链式复述用法:盖住原文,只看钩子链逐句往外说;卡在哪一钩,那一句就是薄弱句,回原文只重背该句。生成自查四条:每段有链、每句有钩、每钩有桥、每钩有锚,缺一不可。

**复习闭环**:`assets/plan-template.html` 自带自包含复习组件(注入于 `</body>` 前,单文件、零依赖),生成方案时**无需手写**,校验两点即可:组件脚本在文件中恰好出现一次(`emm-progress` 标识)、`node --check` 语法通过(**无 node 环境**则以浏览器 `?check=1` 或正则核对 `emm-progress` 仅出现 1 次 + 肉眼确认 `<script>` 闭合正常替代)。组件能力:

- **句级打卡**:第 3 节逐句区每句自动挂「顺 / 卡」按钮,点「开始本轮」进入打卡态;
- **薄弱句清单**:本轮评「卡」自动进清单;清单句连顺 2 轮自动毕业,中途再卡计数清零;
- **轮次结算**:「结束本轮」自动记日期与顺/卡统计,仪表盘显示进度条、轮次历史、薄弱句(点击跳转原文);
- **存储**:进度存 localStorage,键 `emm-progress:<篇名>`,换文件互不干扰;打印自动隐藏全部控件。
**记忆宫殿层**:方案 HTML 第 17 节「记忆宫殿映射」,给钩子链加一条**独立的空间位置线索**,专治随机整句丢失(逻辑线索失效时空间线索兜底)。规则:

- **默认宫殿**:一天生活动线 25 站——起床→卫生间→衣柜→厨房→餐桌→大门→电梯→小区门→公交站→地铁站→闸机→站台→车厢→公司大堂→办公楼电梯→工位→茶水间→会议室→食堂→下楼→超市→公园→回家路→沙发→床。用户可传参替换为自己的熟悉路线;**模板已内置路线引导(v2.29.0)**:首次打开自动弹出「定义我的路线」引导(每行一个站名,保存到 localStorage,之后所有方案自动套用),第 17 节卡片内常驻「✏️ 重新定义我的路线」入口——生成方案时无需手工处理该组件,但要在交付说明里提一句"宫殿站点可以换成你自己的动线"。
- **句站对齐**:直接复用钩子链的句钩+英文锚词(不自造内容),第 n 句放站 n;>25 句的长文启用「同站多物」(同站挂 2 句,句钩区分主次)。**每个站点卡片必须带 `data-sents` 属性**标注承载的 1-based 句号(如 `data-sents="5"`,同站多物如 `data-sents="5,6"`)——薄弱红站联动与 `?check=1` 自检依赖它(v2.15.0)。
- **第 17 节模板**:站点卡片串联(站名+句钩+锚词+句首词),附踩点脚本(闭眼从站 1 走到末站,每站默念句钩)与背法分工(平时走逻辑线=钩子链,卡壳/复习时走空间线=宫殿;「空的站点」直接暴露丢句位置)。
- **联动**:打卡评「卡」的句子,其站点在宫殿区标红(薄弱站重点重修),与复习闭环打通。
**听写验证模式**:方案 HTML 第 3 节逐句区顶部自带「🎧 听写模式」入口(与复习打卡条并列,浏览器 TTS 美音朗读,零配置零依赖):

- **流程**:播放当前句 → 输入听到的英文 →「✔ 比对」逐词高亮(正确绿/错词黄/漏词红删除线/多词灰删除线)→ 全对自动下一句,有错该句自动写入薄弱清单(与打卡共用 `state.weak`,宫殿红站、毕业规则同步生效),可重试;
- **比对算法**:小写化、去标点、常见缩写展开(it's→it is 等双向)、LCS 逐词对齐,输出四态;
- **持久化**:听写进度(句号/错题数/开合状态)独立存 `emm-progress:<篇名>:dict`,打印隐藏控件;
**金句句型库**:方案 HTML 第 14 节(专业词汇之后),每篇精选 5~8 条可复用句型,四列表格:句型(原文摘录,可替换部分加粗)|中文释义|可替换模板|使用场景。选句两类:①实用框架(开场白/警告句/对比句/因果链,可直接迁移到自己的写作演讲);②经典修辞(类比/谚语/排比,值得品味背诵)。「可替换模板」列给换装示范(换主语换话题即复用)。不带测试,保持轻量。章节顺延:记忆钩子=15、复述技巧包=16、记忆宫殿=17,文内交叉引用同步。
**演讲稿模式**:输入被判定为演讲稿时自动启用(判定规则见上方 Step 0 体裁识别表),方案编号变为 16 节——新增**第 3 节「演讲骨架(Speech Skeleton)」**(插在结构图之后、精读之前),其余章节顺延(精读=4…宫殿=16):

- **骨架识别**:按三幕结构分析——开场钩(时间锚/设问/警句)→ 现实语境/论点展开 → 升华收尾(金句/排比/呼吁);每幕标注句子范围与修辞作用;
- **骨架条目格式**:每站含【作用】【技巧】两行——作用=该段在演讲中的功能(蓄力/转折/接棒/收束),技巧=可迁移的演讲手法(如"给任何演讲加时间锚"、"三连否定蓄力");
- **朗读要点**:骨架节末尾固定附朗读指导——呼吸群划分、停顿点、升降调(如排比逐级升调、金句放慢);
- **问题链改造**(第 6 节):按"观众视角的接下来呢?"组织,6 个路标问题对应演讲推进;
- **复述阶梯改造**(第 7 节):L3 改为「看骨架说」——只看骨架六站复述整段,契合演讲线性记忆;
- **样例参照**:`gettysburg-memorization-plan.html`(葛底斯堡演说,三幕结构+三连否定+三介词排比)。
**长文模式**:文章 500~2000 词、或 >15 句、或 ≥3 段时自动启用,方案变为 17 节——核心是「**全局框架 + 按段展开**」:

- **章节布局**:1 整体策略(含分段排期建议:每天 1~2 段,**不写死日期**——精确到期由「📅 今日任务」卡按开始日期自动计算,v2.15.0)→ 2 全篇结构图 → **3 分段进度仪表**(新增)→ 4.1~4.N 段落单元 → 9~17 全局节(三遍法/按段排期艾宾浩斯/挖空/短语/术语/金句/跨段总链/复述技巧/宫殿跨段连续);
- **段落单元(4.x)**:每段独立闭环——逐句精读(全现象标注)+ 关键词表 + 问题链 + 三层钩子链;段=意群单元(按主题/论证转折切分),单元标题只含段名(不含排期日,排期由组件计算);
- **分段进度仪表**:每段一行——段名/排期(固定写「📅 自动」)/状态徽章(🔒未开始 → ▶ 进行中 → ✅ 已背)/打卡入口/段薄弱句数;状态由打卡结算自动驱动(该段全部句子在本轮评「顺」→ ✅;有任何判定或弱句 → ▶),数据存 localStorage 与现有组件同源;未开始的段默认 🔒;
- **按段艾宾浩斯**:每段独立复习周期(当晚→次日自测→第 3 天错句→第 7/15 天),错开进行,单日总量不超标;最后加「全文合体」日;**精确到期日以今日任务卡为准,艾宾浩斯节写机制、不写死日期**;
- **跨段总链**(第 15 节记忆钩子内):把各段段钩串成全篇 3~8 站总链,先背总链再进各段;
- **宫殿跨段连续**:站点编号跨段累加(站 1 = 全篇第 1 句),不做段内重置;
- **样例参照**:`declaration-memorization-plan.html`(独立宣言背诵精编版,5 段/21 句/~830 词)。
**自测与排期套件**:方案 HTML 组件自带四件能力(注入于 `</body>` 前,生成时无需手写),专治"背不完、假流利":

- **自测模式**:复习打卡条新增「🙈 自测」三档循环(关→遮译文→全遮)。遮住全部中文翻译与连读注解,点句子临时揭开核对——把打卡从"看着原句评顺卡"变成"盖住→复述→揭开→评顺卡",消灭"认出式假流利";全遮档同时压平行内标注样式,原文变纯净文本。

**触发**:用户说「考我 / 陪我练 / 抽查 / 提问 / 我说给你听 / 复述给你听 / quiz me / explain back」;或交付方案后用户回「开始」。未触发时不要自作主张开始提问。

**七条硬规则(不可违反)**:

| # | 规则 | 可执行判据 |
|---|---|---|
| 1 | **一次一问** | 每轮只出 1 个问题,等用户回答后才揭晓答案/下一题;禁止把题目和答案同时给出 |
| 2 | **等答再揭** | 用户未作答前不显示原句、译文、钩子链或任何提示;用户要提示时只给句钩/锚词,不给整句 |
| 3 | **三档诚实评分** | 正确 / 部分正确(必须点明缺了什么) / 错误;不许笼统说「差不多」「挺好的」 |
| 4 | **问理解,不问琐碎** | 优先问「这句为什么在这」「抽掉它链条断在哪」「换个说法还成立吗」;纯数字/名词裸回忆 ≤ 1/4 |
| 5 | **原文唯一真相源** | 只用方案 `.sent-en` / 三层钩子链 / 挖空答案出题与纠错;禁止拿原文外的背景知识判错;用户异议且原文支持时须认错改判 |
| 6 | **结算三要素** | 每轮结束必给:得分(答对/总)、最弱句(带 1-based 句号)、下次到期(按艾宾浩斯表推算,非读取浏览器) |
| 7 | **能力诚实** | 宿主 Agent **读不到浏览器 `localStorage`**(`file://` 页面与对话进程隔离);无用户显式提供的进度数据时,禁止虚构句号/到期日冒充「你的进度」 |

**能力边界(v2.37.1 修正)**:上一版把出题顺序写成读 `state.weak` / SM-2 `due`,但对话进程拿不到浏览器存储,该链路实际不可执行。现改为**双档**,默认档零依赖、L1/L2/L3 通吃。

**出题池 · 静态档(默认,无需任何外部数据)**:
1. 题源只用**方案文件里可见的内容**:`.sent-en` 原句、三层钩子链、挖空段、结构图、金句句型库(L2/L3 用 Markdown 精简版对应模块);
2. 顺序=按段**均匀铺开并交错**(A→B→C→A),不要从头连着问 8 句;先钩子链复述、再理解型;
3. 单轮默认 8 题,用户可指定;答错记入本轮薄弱,结算时统一列出句号。

**出题池 · 动态档(仅当用户主动提供进度)**:用户贴出方案页「💾 导出」的进度 JSON、或直接粘贴薄弱句清单/到期日后,才按 **due-first** 排序:
1. 先出到期复习句:`state.weak` 薄弱句 → 今日任务卡到期段 → 标准模式 SM-2 `due ≤ 今天` 的句;
2. 再出未覆盖的新句,仍保持跨段交错;
3. 用户没贴数据就**不要问**「要不要我读一下你的进度」,直接走静态档;不得据此编造「系统显示你第 3 句薄弱」。

**题型配比**(每 8 题):钩子链复述 3(给句钩+锚词说出原句)、理解型 2、挖空填空 2、L5 转述/费曼 1。

**Feynman 深挖(v2.40.0,对话版)**:当某段阶梯已到 L5(或用户主动说「费曼这一段」),对该段执行三连追问链——①不看原文大白话复述整段;②追问钩子链逻辑桥「为什么这样衔接」;③换场景/反例「换个语境还成立吗」。答不上来的句子,结算时列出句号并引导「回原方案点 🎤 Feynman 补卡」——HTML 侧同名模式(复习条 🎤 按钮)会把点名卡句写入薄弱清单,对话侧只列句号不落盘,分工与上表一致。追问深度优先于覆盖面:一段三连追问到位才算过,不许三连全跳。

**与 HTML 方案的分工(勿破坏)**:陪练**不写也读不到 localStorage**、不改 `state.weak`、不冒充打卡——会话内判定只在结算里列出句号,引导用户「回原方案补打卡」(可带 `?jump=0,2,5` 直达);与记忆库「轻刷不落盘」同一设计原则。

**结算模板**(「下次到期」按艾宾浩斯表推算,静态档也适用):

```
本轮 6/8 · 最弱:第 3 句(漏了逻辑桥 but) / 第 7 句(锚词误说成 ...)
按排期下次到期:明天(次日自测) · 回原方案把这 2 句评「卡」→ 薄弱快刷 5 分钟
```

## 倦怠检测与换法阈值(v2.37.0)

> 借鉴 `kaixiad/RetainCraft`(倦怠检测 / 评分纪律 / L5 费曼检验)、`lyndonkl/claude`(3 轮后保留率 <60% 换方法)。

**倦怠触发(任一即生效)**:

| 触发 | 响应 |
|---|---|
| 连续 3 句评「卡」 | 降一档:L4→L3 / L3→L2,或切「⚡ 只刷薄弱」5 分钟短会话 |
| 连续 2 轮正确率下降 | 暂停新学,只做已学段复习;复习会话砍到 5 分钟 |
| 用户说「累了 / 太难 / 背不动」 | 停 60 秒换活动(减压阀),回来只背主线 70%(减量) |

**换法阈值(关键:不是继续重背)**:连续 3 轮复习后该段保留率仍 <60% → 判定**方法失配**,回到 Step 2 重做钩子链(优先查「桥接不上的链条=断点」)或换链式化策略(问题链↔电影法↔轨道法),而不是把同一段再背第 4 遍。给用户一句结论:「不是背得不够,是这条链没焊上」。

**L5 费曼检验**(替代「说够 90 秒即算过」):L5 需同时满足 ① 连续 2 轮全文空手复述 ≥90%;② 通过费曼三问——

1. 这句为什么在这个位置?(逻辑角色)
2. 抽掉它,钩子链哪一环会断?(结构依赖)
3. 换个词/换个说法还成立吗?(能转述而非背字)

三问由 AI 扮演「不懂的学生」追问,答不出即退回 L4;评分标准开始前公布、过程不改。L2/L3 环境用文字自问自答等价执行。

## 平台能力分级与 Markdown 精简版(L2/L3 兜底)

> 21 平台能力不均:L1 平台直装 HTML 拿完整体验;L2 平台(Cursor/Copilot/Gemini CLI/Cline/Aider/Roo 等规则注入型)只能收到 **Markdown**;L3 平台靠用户手动复制。若在 L2/L3 环境生成,禁止交付"残缺的 HTML 指令",改交**Markdown 精简版**——保住方法论内核,砍掉依赖 HTML/浏览器的交互。

| 层级 | 平台类型 | 交付形态 |
|---|---|---|
| L1 | 直装 skill 的平台 | 完整 HTML 方案(模板全组件) |
| L2 | 规则注入 / 项目级 Markdown 平台 | **Markdown 精简版**(见下) |
| L3 | 手动跟随 | Markdown 精简版 + 聊天内讲解 |

**Markdown 精简版必备模块(按序,一个不能少)**:

1. **3 步快背路径**(听读 → 钩子链 → 复述打卡)——新手入口,永远放最前
2. 逐句钩子表:`原句 | 关键词钩子 | 中文提示`(每段一张 Markdown 表)
3. 三层钩子链:每段一条,格式 `句钩 ⇒桥 [锚词]`(桥符号见表下注)
4. 复述五级阶梯 L1→L5(看关键词说 → 看骨架说 → 看标题说 → 空手说 → 限时说)
5. 挖空自测:每段 2~5 空,`______` 表示,答案包在折叠块(`<details>` 或"下拉可见"标注)里
6. 三遍法 + 艾宾浩斯复习计划(紧凑表格)

**精简版明确不做(并告知用户差异)**:SVG 结构图(改用文字骨架:每段一行主线)、听写/影子跟读/打卡/SM-2/进度导出等 HTML 专属交互(改用"自己录音 + 纸笔自测"的口头替代法)、记忆宫殿可视化(保留 25 站文字清单)。交付时附一句:"完整交互版(听写/录音打卡/间隔算法)可在支持 HTML 的平台生成,要的话说一声。"
> **例外**:「对话陪练协议」只依赖聊天,不依赖 HTML——L2/L3 照常可用(逐句问、三档评分、费曼三问、结算给最弱句),这是精简版保住**主动回忆**的主要通道,不得一并砍掉。

> 各平台能力差异的完整声明见 `platforms/README.md` 与 `readme.md`「已知局限与适用边界」章节;生成前若不确定当前平台属于哪级,按 L2 处理(交 Markdown 精简版不会错)。

## 逐句翻译与全现象连读标注规范(v2.1)

背诵方案原文区的每一句是一个三层块,顺序固定:

1. `.sent-en` 英文句(行内语音标记版,见下)
2. `.sent-zh` 中文翻译(灰字 + 左侧竖线,背诵核对用)
3. `.pron` 连读注解行(浅底色块,含音标与读法)

**行内标记体系**(只改样子,不替换原词;原文永远保持可背诵的完整形态):

- 连读:词间橙色弧线 `⌒`(辅音+元音、r 连读、元音+元音滑连同用 ⌒,注解里标注类型)
- 弱读:词用灰色斜体(元音弱化为 /ə/ 的功能词)
- flap t / 失爆:t 红色波浪线(注解区分闪音 [ɾ] 与失爆)
- h 击穿:h 灰色虚线下划
- 缩读:原词不动,变体只出现在注解行,格式 `want to → wanna /ˈwɑːnə/`

**规则**:

- 音标一律用美式 IPA;注解格式 `片段 音标 · 现象名(读法要点)`
- 每句注解 ≤6 条,超出时优先保留影响听辨的现象
- **存疑不标**:连读/弱读/flap t/击穿只标有把握的现象,准确性优先于覆盖度——一处错标会摧毁用户对全部标注的信任,拿不准的宁可不标
- 翻译默认中文;用户可传参指定语种(如"出背诵方案,翻译成日语"),参数只影响翻译层
- 翻译直译优先、忠实原意;代词在翻译中还原所指
- 原文区顶部放图例条:`⌒ 连读 · 灰斜体 弱读 · 红波浪 flap t · 灰虚线 h 击穿 · ⇒因果 / ↔转折 / →递进 / ＋并列 / :举例(钩子链逻辑桥,见第 15 节)`——逻辑桥符号必须进图例,非语言学背景的学习者看得懂"钩子之间怎么接"

## 结构图规范(SVG)

- 画布 1200 宽;每段一列(≤4 列),4 列时列宽 260、3 列时列宽 353,列间距 30。
- 每列 2~3 个节点框(高 84、圆角 10、白底、彩色描边 2px),框内:英文 1~2 行(每行 ≤35 字符,font-size 13.5,加粗)+ 中文提示 1 行(font-size 12.5,灰色)。
- 同列节点间竖向箭头(`<line>` + marker-end),列头为浅色胶囊标题("第 N 段 · 逻辑角色")。
- 底部深色横幅(高 76):核心线索一行 + 逻辑路标/金句一行;横幅下方一行背诵口诀。

## 内容校验(生成后强制执行,v2.13.0)

方案写完、交付前逐条跑完下列校验;任何一条不过,修复后再交付。

**第 0 步 · 机器硬门禁(交付前强制)**:运行 `node bin/verify-plan.mjs <方案.html> --source <原文.txt>`(等价 `npm run verify -- <方案.html>`)——它自动核对下方规则 1/3/4/5/6 的机器可查部分(逐句对照/宫殿对齐/钩子链/挖空配对/词句溯源);**退出码非 0 = 存在 error 级失败,修复后重跑直至退出码 0,禁止带病交付**。支持目录批扫:`node bin/verify-plan.mjs <输出目录>`(自动匹配 `*-memorization-plan.html`)。无 node 环境时以浏览器 `?check=1` 报告 + 下方逐条人工复核替代,不得静默省略。

用户可在浏览器打开 `plan.html?check=1` 查看 DOM 侧自检报告(分段识别/宫殿/钩子链/挖空空数),其中 ①② 必须在生成端完成:

1. **逐句完整性**:抽取全部 `.sent-en` 的文本(行内标注 span 只改样式不换词,textContent 即原句),与原文逐句对照——**句数相等、每句去首尾空白后逐字符一致**;禁止意译、缩写、漏句、多句。
2. **标注精度**:连读/弱读/flap t/击穿按"存疑不标"复核一遍;音标抽查 ≥3 处。
3. **宫殿对齐**:每站 `data-sents` 标注齐全、每句恰好被一站覆盖(>25 句同站多物时一站可含 2 句);站号 1..M 连续(长文跨段累加);每站句钩与锚词和钩子链同句一致。
4. **钩子链对齐**:每段句钩数==段内句数;相邻句钩之间有逻辑桥;每钩挂 `[英文锚词]`。
5. **挖空可核对**:每段挖 2~5 空;`______` 个数==答案词数;每个答案词确实出现在被挖的原句中。
6. **词汇与金句溯源**:专业词表每个词、金句句型库每条"原文摘录",都必须能在原文中找到。
7. **版本戳与截断防护**:① 方案页脚须渲染版本戳(模板 JS 会自动注入,与 `plan-template.html` 顶部版本一致,如 `v2.29.0`),便于回溯"我跑的是哪版";② 记叙文若含裸 `</`(代码/URL/XML 片段),确认其位于 HTML 正文区(`.sent-en` 等 div)而非 `<script>` 数据串——落在数据串中的 `</` 一律写成 `<\/`,否则会提前闭合脚本(同类检查见下方记忆库第 5 项)。

生成端抽句对照示例(node):

```bash
node -e 'const fs=require("fs");const h=fs.readFileSync(process.argv[1],"utf8");(h.match(/<div class="sent-en"[^>]*>[\s\S]*?<\/div>/g)||[]).forEach((s,i)=>console.log(i+1,s.replace(/<[^>]+>/g,"").replace(/\s+/g," ").trim()))' <topic>-memorization-plan.html
```

> 无 node 环境时,用浏览器控制台执行等价逻辑,或正则提取每个 `<div class="sent-en">…</div>` 块文本逐句对照原文(效果等同上条命令)。

## 个人记忆库(memory-library,v2.17.0)

把用户工作区里所有背诵方案汇总成一份自包含的 `memory-library.html`:书架卡片 + 关键词搜索 + 每篇"轻刷"(链回忆→挖空挑战→结算)+ 实时进度。

**触发**:用户说"生成记忆库 / 更新记忆库 / 复习库 / 汇总我的方案 / library"时执行;生成新方案交付后可顺带问一句是否更新记忆库。

**流程**:

1. **扫描**:在工作区(方案输出目录)找全部 `*-memorization-plan.html`;一篇都没有时提示先生成方案,不产出空库文件。
2. **逐篇提取**(读方案文件,按 `assets/library-template.html` 文末 schema 组装每篇数据):
   - `key`:**逐字复制方案 `<h1>` 文本去首尾空白后的前 40 字**——进度键 `emm-progress:<key>` 必须与方案组件 `keyOf()` 完全一致,错一字进度就永远读不到;
   - `file`:方案文件名(相对路径);`title`/`topic`/`type`(议论文/说明文/叙事文/演讲稿/长文)/`sents`(.sent 块数)/`words`(约)/`date`(方案生成日期);
   - `chain`:与方案第 15 节三层钩子链**逐字一致**,每段一条 `{para, steps:[{h 句钩, b 逻辑桥, a 锚词, sidx 句号, en 原句英文全文}]}`;`en` 从方案 `.sent-en` 取 textContent(即纯原句);
   - `cloze`:1~3 条,优先复用方案第 11 节挖空自测的段落与答案(`q` 含 `______`,`a` 与空按出现顺序一一对应);方案没有挖空段时现挖 2 句钩子词位置的空。
3. **填充与交付**:复制 `assets/library-template.html` 为 `memory-library.html`,填 `{{DATE}}`(今天)与 `{{ARTICLES}}`(每篇一个对象,逗号分隔,置于与方案相同的目录);交付时说明:轻刷结果不落盘,打卡与薄弱清单永远以原方案为准。

**进度机制(关键设计,勿破坏)**:记忆库**不填充任何进度数据**——打开时运行时读本机 localStorage 的 `emm-progress:*` 键(所有 file:// 页面同源共享,桌面端 Chrome/Edge 即开即得),显示每篇打卡轮数/薄弱句数/进度条/最近活动,超 14 天未复习给"⏰ 建议回温"徽标。手机端打开时若浏览器不给 file:// 存储,进度区优雅降级为"尚未打卡",轻刷不受影响。**同名陷阱**:进度键取 h1 前 40 字,两篇文章 h1 前 40 字相同就会共享同一进度——生成记忆库时检查 key 是否有重复,有则提醒用户并建议改方案 h1 使其可区分。

**轻刷原则**:会话内有效、**不写 localStorage**——轻刷里标记"卡了"的句子只在结算里列出(带句号),引导用户"回原方案补打卡"进真正的薄弱清单;禁止为图方便直接改写方案进度状态。

**校验(交付前强制执行,任一不过先修复)**:

1. `EMM_LIBRARY_V217` 标识恰好出现一次;`node --check` 通过(**填充后**再校验,模板占位符本身不是合法 JS;无 node 环境改浏览器 `?check=1` 或正则核对 `EMM_LIBRARY_V217` 仅出现 1 次);
2. 每篇 `key` 与对应方案 `<h1>` 前 40 字逐字一致(抽查 ≥2 篇,打开方案文件对照),且各篇 `key` 互不重复;
3. 每篇 `chain` 句钩总数 == 该篇 `sents`;`cloze` 每条空数 == 答案数;
4. `memory-library.html` 与方案文件同目录(`file` 相对链接可点);
5. **`</script` 截断检查(硬性,v2.28.1)**:填充后的 `memory-library.html` 中 `</script` 必须恰好出现 **2 次**（v2.34.0 起：EMMProgressStore 注入块 + 主脚本）——数据字符串里出现 `</` 一律写成 `<\/`,否则 HTML 解析器会在字符串内部提前闭合脚本,整页 JS 静默挂掉(书架空白),而 `node --check` 与浏览器外提取都查不出来。校验命令(输出必须是 2):
   ```bash
   node -e 'const h=require("fs").readFileSync(process.argv[1],"utf8");console.log((h.match(/<\/script/g)||[]).length)' memory-library.html
   ```
6. 用户打开 `memory-library.html?check=1` 可见数据体检报告(每篇 key/file/链句数/挖空配对逐项 ✅/⚠)。

## 记忆力友好包(面向记忆弱的学习者)

- **减量**:先只背主线 70%--每个意群只锁 1 个核心词,修饰语靠语法和逻辑推。先粗后细,比一次全背更牢。
- **画面化**:每个钩子变成 1 秒画面,越具体越荒诞越好--图像记忆是人类的母语。
- **自己编**:用户自己写的问题清单/自己编的电影画面,记忆强度约翻倍(生成效应)--AI 给的方案只是示例,改造动作必须用户亲手做。方案内「✍️ 我的一句话主线」「🎨 我的画面」留白(v2.13.0)就是为此准备的,交付时明确督促用户亲手填写。
- **减压阀**:背不动时停 60 秒做别的再回来;漏一天不清零,第二天接着来;忘掉 20~40% 是正常甜区(见「复习调度硬规则」规则 5)。触发「累了 / 连卡 3 句 / 连续 2 轮降分」时按「倦怠检测与换法阈值」降档,不要硬扛。
